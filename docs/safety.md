# 安全边界

## 基本原则

本项目处理的是本机隐私数据，默认策略必须保守：

- 不修改真实微信数据库
- 不删除真实微信文件
- 不直接在真实微信数据库上建立可写连接
- 不默认全量导出明文聊天记录
- 不把聊天内容发送到外部服务
- 所有输出默认写入 `TEST`

## key 的用途

key 只是读取能力的凭证，不应该等同于默认全量导出。推荐用途是打开解密副本，建立本地索引，并按需做搜索、摘要和提醒。

key 缓存文件：

```text
TEST/key-cache.json
```

缓存中的 key 使用 Windows 当前用户 DPAPI 加密。换用户、换系统或迁移到其他机器后通常不可直接解密。

## Hook 风险

`--unsafe-hook-key-extract` 是高风险路径。它会临时 Hook 正在运行的微信进程来获取 key，可能造成：

- 微信卡顿或崩溃
- 微信掉线
- 安全软件拦截
- 微信版本更新后失效

因此该流程必须满足：

- 用户显式传入参数
- 执行前再次确认
- 成功后写入 key 缓存
- 同一微信号后续优先读取缓存，不再默认 Hook

## 避免误写入

所有读取数据库的工具都应遵守：

- 输入目录优先使用 `TEST/decrypted-db`
- 拒绝把真实微信目录作为输出目录
- SQLite 连接使用只读模式
- 连接后设置 `PRAGMA query_only=ON`
- 输出文件只能写入 `TEST` 或用户显式指定的安全目录

## 避免锁库

不要直接用 SQLite 打开真实微信正在使用的数据库。推荐流程是：

```text
真实微信目录只读复制
  -> TEST 下处理副本
  -> 后续查询、索引、总结都只访问副本
```

如果需要复制数据库，必须同时考虑相关文件：

```text
*.db
*.db-wal
*.db-shm
```

这样可以降低读取不完整或锁冲突的概率。

## 输出控制

默认不应生成大范围明文导出。更推荐生成：

- 小时笔记
- 待办列表
- 日程候选
- 搜索结果引用
- 按需导出的少量会话片段

全量 HTML、TXT 或 Markdown 导出仍然保留，但应作为显式操作，而不是自动化默认动作。
