# 架构说明

## 目标

本项目的目标不是全量导出聊天记录，而是在本机安全地读取微信数据，建立可搜索、可总结、可提醒的本地聊天记忆。

推荐主链路：

```text
真实微信目录
  -> 只读复制或解密到 TEST
  -> 增量抽取消息
  -> 本地结构化索引
  -> 本地语义索引
  -> 本地模型总结、搜索、日历和笔记
```

## 模块边界

```text
tools/safe_decrypt.py
  负责 key 缓存、只读读取真实微信目录、把解密副本写入 TEST。

tools/wx_key_cli/
  负责在用户显式确认后临时获取微信 key。成功后 key 写入缓存，后续不再默认执行 Hook。

tools/safe_export.py
  负责从 TEST 下的解密库导出 HTML / Markdown / TXT。它不是长期记忆助手的核心入口。

tools/chat_memory_index.py
  计划新增。负责把消息增量写入 TEST/chat-memory/memory.db。

tools/hourly_assistant.py
  计划新增。负责读取最近一段时间的消息，调用本地 LM Studio 生成笔记、待办和日历候选。
```

## 数据分层

### 原始数据层

原始微信数据库位于用户的微信目录，例如 `xwechat_files` 下。项目只能只读访问这一层，不允许写入、删除或建立可写数据库连接。

### 解密副本层

解密后的数据库放在：

```text
TEST/decrypted-db/<account-root>/db_storage
```

这是后续处理的主要输入。主工具应该只读取这一层。

### 本地记忆层

计划新增：

```text
TEST/chat-memory/
  memory.db
  notes/
  calendar/
  state.json
```

`memory.db` 保存结构化消息、联系人、会话、标签和处理状态。`notes` 保存小时笔记和日总结。`calendar` 保存 `.ics` 或日历候选 JSON。`state.json` 保存上次处理窗口和去重状态。

## 检索方案

长期方案采用混合检索：

```text
SQLite 精确查询
  + 关键词召回
  + 向量语义召回
  + 本地模型重排
  + 原始消息引用
```

不要只做 RAG。RAG 适合模糊语义搜索，但不适合精确时间、联系人、消息类型、审计引用和去重。SQLite 索引负责事实边界，向量索引负责语义召回，本地模型负责总结和排序。

## 小时助手流程

每小时运行一次时，建议读取最近 75 到 90 分钟消息：

```text
读取窗口
  -> 结构化去重
  -> 过滤文本和有用消息
  -> 补充联系人和群聊名称
  -> 调用本地模型
  -> 写入小时笔记、待办和日历候选
```

读取窗口大于 60 分钟是为了避免任务计划延迟、微信写库延迟或上次运行失败导致遗漏。重复处理由消息 ID、时间、会话和内容哈希共同避免。
